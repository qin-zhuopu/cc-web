## SK · Shared Kernel 要点

- **目录**：`packages/core/shared-kernel/{domain,ports}`
- **7 个端口**（多为出站端口，适配器实现）：ErrorClassifier、Platform、Redactor、TranslationPort、RuntimeLog、Clock、IdGenerator
- **领域**：ErrorCode 16 类枚举（NETWORK/TIMEOUT/RATE_LIMIT/AUTH/PERMISSION/INVALID_REQUEST/NOT_FOUND/CONFLICT/SERVER/UNAVAILABLE/QUOTA_EXCEEDED/RESOURCE_LIMIT/FILESYSTEM/PROCESS/**ABORTED**/UNKNOWN）、ClassifiedError、LogEntry
- **适配器**（apps/api）：SystemClock、UuidGenerator、RegexRedactor、JsonTranslationTable、RingBufferRuntimeLog、NodePlatform
- **铁律**：零框架/零业务依赖，禁 import @nestjs/better-sqlite3/anthropic/uuid，不反依赖 C1-C10
- **史诗**：4 史诗 12 故事（E1 错误+类型 → E2 Clock/Id/Platform → E3 脱敏+日志 → E4 i18n+接线+C7 试点）

## C1 · Conversation 要点

- **目录**：`packages/core/conversation/{domain,ports/{driving,driven},usecases}`
- **领域**：ChatSession 实体（只含会话本体 10 字段）、Message、MessageContent（5 类块 text/thinking/tool_use/tool_result/code + encode/decode）、StreamStatus（持久生命周期）、TitleOrigin（default<ai<user 覆盖优先级）
- **驱动端口**：ManageSessionUseCase、SetSessionTitleUseCase、AppendMessageUseCase、GetSessionHistoryUseCase（含 getPromptView 剔除 render-only）
- **出站端口**：SessionRepository、MessageRepository；依赖 C2.TitleGeneratorPort（import type）
- **字段归属纪律**：sdk_session_id/codex_*/runtime_status/provider_id/permission_profile/context_summary 等**不进** C1 领域模型，归各自上下文
- **铁律**：不含 phase/StreamSession 概念（切断 stop/abort 误用）；禁 import SDK/DB/框架/Date.now/randomUUID
- **史诗**：6 史诗 27 故事（E1 骨架 → E2 MessageContent → E3 会话生命周期 → E4 标题状态机 → E5 消息生命周期 → E6 NestJS 接线）

## C2 · AgentRuntime 要点

- **目录**：`packages/core/agent-runtime/{domain/{stream,event,runtime},ports/{driving,driven},usecases}`
- **领域核心**：
  - `StreamPhase` 状态机：active → settling → terminal{completed/aborted/errored}，只经领域方法迁移
  - `StreamSession` 聚合根：`canAccept()` ≡ phase!==active；`markSettling/complete/abort/fail`
  - **abort 不变量**：任意 abort 路径后 phase 必落 terminal，绝不停 active（根治 GitHub #578 卡死）
  - `AgentStreamEvent`：14 类事件联合（text/thinking/tool_use/tool_result/tool_output/status/result/error/permission_request/permission_resolved/context_usage/rate_limit/file_changed/phase_changed）
  - `TerminalReason`（6 类归因，映射 SK.ErrorClassifier：user_aborted→ABORTED、idle_timeout→TIMEOUT、tool_timeout→PROCESS/TIMEOUT、process_died→PROCESS）
- **驱动端口**：StartStreamUseCase、AbortStreamUseCase、TitleGenerator（供 C1）
- **出站端口**：AgentRuntimePort（run/interrupt/forceKillTurn/availability，供 C3 复用）；依赖 C1 用例、C7.ProviderRepository（只读，import type）
- **适配器**（apps/api）：ClaudeSdkRuntimeAdapter、NativeRuntimeAdapter、CodexRuntimeAdapter，各带 EventMapper；RuntimeRouter 按 RuntimeKind 路由
- **AbortStream 编排**（#578 结构化沉淀）：force-abort 安全网**无条件先行** → markSettling → best-effort interrupt → reconcilePhase 收敛。force-abort 绝不排在 interrupt 的 .finally 后
- **铁律**：phase 内存态不落库、不与 C1 StreamStatus 混用；禁 import @anthropic-ai/better-sqlite3/@nestjs/child_process/codex/Date.now/randomUUID；进程复杂度全锁在 CodexRuntimeAdapter
- **史诗**：7 史诗 40 故事（E1 骨架 → E2 phase 状态机 → E3 事件模型 → E4 发起回合 → E5 中断回合 → E6 三适配器 → E7 TitleGenerator+权限+接线）

## 三大关键设计决策（速查）

1. **phase 状态机根治 abort 卡死**：StreamPhase 做成 StreamSession 聚合根的领域不变量，abort 幂等强制翻终态，`canAccept() ≡ phase!==active`，force-abort 无条件先行——正是 GitHub #578 的结构化修复。
2. **C1 持久 StreamStatus vs C2 实时 phase 分离**：C1 类型层不含 phase，切断 stop/abort 误用根因。「现在是否在流式」只能问 C2。
3. **反假数据契约**：C1/C2 的 PRD §0 定义每个用户可见字段的语义/真实来源/缺失降级——token/上下文用量无实测来源时留空而非假 0；ABORTED 与真实错误在 UI 上必须可分。
