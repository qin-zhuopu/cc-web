# 06 · 关键决策与硬约束

本文件汇总实现阶段必须遵守的所有决策与约束，供开发时直接对照。

## 4 项技术决策（经 AskUserQuestion 确认）

| 维度 | 决策 | 说明 |
|---|---|---|
| 持久化 | TypeORM + SQLite | better-sqlite3 driver，本地文件；适配器层，不进核心包 |
| 流式传输 | SSE | 单向 server→client，NestJS @Sse() / raw response；非 WebSocket |
| SDK 能力范围 | 完整消息流 | 透传 text/thinking/tool_use/tool_result/system/result；本期不含 MCP 配置、权限审批交互 |
| 活跃 vs 历史 | 按是否正在流式响应 | 活跃 = 内存注册表有活跃 Query 句柄（C2 phase=active）；历史 = DB 全量 |

> 注：持久化选 TypeORM 是原生 plan 阶段的决策。走六边形规划后，持久化实现属 apps/api 的 SqliteSessionRepository/SqliteMessageRepository 适配器；用 TypeORM 还是直接 better-sqlite3 属适配器内部选择，不影响核心包（核心只依赖 Repository 端口接口）。开发时再定。

## 六边形架构铁律（最高优先级）

- `packages/core/*`（shared-kernel / conversation / agent-runtime）**禁止 import**：
  `@anthropic-ai/*`、`better-sqlite3`、`@nestjs/*`、`node:child_process`、codex SDK
- **禁止直接**用 `Date.now()`、`new Date()`、`crypto.randomUUID()`、uuid 库
  —— 时间经 SK.Clock，ID 经 SK.IdGenerator
- SDK / DB / 进程 / HTTP / 框架细节**全部锁在 apps/api 的适配器层**
- 每个核心包要有**禁用 import 的静态扫描守卫**，纳入 `npm run test` 门禁（SK-S4.3、C1-S1.7、C2-S1.7）

## C2 本期 Runtime 约束（用户指定）

- **本期只实现 ClaudeSdkRuntimeAdapter** 一个 Runtime 适配器
- Native、Codex 适配器**本期延后**
- 但 `AgentRuntimePort` 接口 + `RuntimeRouter`（按 RuntimeKind 路由）**保留**——将来加 Native/Codex 不改核心。这是六边形架构的预期收益
- Windows 兼容必须做：移植 CodePilot 的 `resolveScriptFromCmd`（解析 .cmd wrapper 拿 cli.js 真实路径给 pathToClaudeCodeExecutable）

## 依赖顺序（硬）

```
SK（无依赖）
  → C1（依赖 SK + C2.TitleGenerator 接口）
    → C2（依赖 SK + C1 用例 + C7.ProviderRepository 只读）
```

- **C1 ↔ C2 循环依赖**：C1 需 C2.TitleGenerator、C2 需 C1.AppendMessageUseCase/GetSessionHistoryUseCase。NestJS 两侧 `forwardRef` 在接线层解，核心包只单向 `import type`，无实现级环。
- **C7 缺口（需在冲刺规划决策）**：C2 的 StartStreamUseCase 依赖 C7.ProviderRepository（只读，解析 providerId → 协议/endpoint/auth/model）。但本期未做 C7。方案二选一：
  1. 提供一个最小 C7 stub / ProviderRepository 假实现（够 C2 跑通 Claude SDK 一路）
  2. 简化 provider 解析（本期直接从 env / 固定配置取 Anthropic 凭据）
  推荐先做最小 stub，保持 C2 依赖端口不变，将来补全 C7 无缝替换。

## 测试铁律

- 核心用例用**假出站端口**（内存 FakeSessionRepository/FakeMessageRepository/FakeAgentRuntimePort）+ 假 Clock（固定时刻）/假 IdGenerator（序列）/假 TitleGenerator 做纯单元测试，无需真实 SDK/DB/网络
- C2 必测反例：**注入 interrupt 永不 resolve 的假 Runtime + 假 Clock 推进 force-abort，断言 abort 后 phase=terminal(aborted)、canAccept()=true**（复现并回归 GitHub #578）
- 反假数据 smoke：无 tokenUsage 时字段留空、断言 UI 不出现假 0
- 归因分类反例：ABORTED vs TIMEOUT vs PROCESS 三路 ClassifiedError.code 不同
